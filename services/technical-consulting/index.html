Process

Understand → isolate → recommend → verify

I start with the current system and the actual failure or business constraint. The goal is to identify the smallest justified change, document the dependencies and verify the result instead of replacing working components by default.

Deliverables

Depending on the task: written findings, architecture notes, implementation priorities, risk list, troubleshooting steps, deployment plan or a verified technical fix.

FAQ

When consulting is the right first step

Do I need a full project?

No. A focused technical review can be used to understand the problem before committing to implementation.

Can you work with an existing setup?

Yes. Preserving stable parts of an existing system is preferable to rebuilding without evidence.

Can the review lead to implementation?

Yes. If the findings are clear, the next phase can be scoped as a separate implementation with defined responsibilities.
